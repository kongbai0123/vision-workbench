# 訓練時間估算與快速評估

[返回 README](../README.md) · 2.20.0 · 2026-09-24

06 提供「快速估時（不訓練）」。符合條件的歷史紀錄可在啟動前提供初估；實際執行後由首個完成的工作單位提供觀測值，持續修正 ETA。時間是預估，不能保證確切完成時刻。本次開發只做時序回放與隔離介面測試，沒有啟動訓練或下載權重。

## 演算法與資料來源

進度使用已完成 Batch／總 Batch、驗證輪數或影像數。ETA 不再由介面輪詢時間、整數 Epoch 比例或 5%–87% 的人工加權進度反推。

1. **tqdm 實際速度**：固定 `tqdm==4.70.1`，使用其計數器及速度估算，透過 `format_dict` 取得資料。每階段有自己的有效時間，驗證與排隊不會混入 Batch 速度；不解析終端機文字。
2. **多種速度估計**：以 α=0.15、α=0.5 的指數移動平均與累計平均建立三個候選。每次更新先評估上一個預測與新觀測的絕對誤差，再更新候選；保留最近 16 次誤差，以誤差倒數平方加權。這是專案採用的線上組合策略，並非 tqdm 內建的整體工作預測器。
3. **快速初估**：第一個完成單位後即可提供時間，前 4 個有效樣本標示「快速初估」；其他時候標示「動態預估」。首次工作還没有歷史資料時，不會執行微型訓練來測速。
4. **分階段相加**：資料／模型準備、訓練、每輪驗證、引擎最終檢查、權重保存、最終 Validation、Test、結果保存分開記錄。所有未完成階段都有速度或歷史資料時才顯示「全程剩餘」；否則清楚標示目前階段的剩餘量。
5. **歷史初估**：最多讀最近 30 個 Run 的小型狀態檔，採用 30 天內最多 12 次符合條件的完成紀錄，以各階段每單位耗時的中位數建立初始值。不讀圖片內容、不啟動環境探測程序，也不載入模型。
6. **環境與設定隔離**：比對 manifest SHA-256、引擎、除 epochs 外的完整有效設定，以及本機／Python／關鍵套件檔案指紋。只有輪數可按工作量縮放；換 Batch、尺寸、裝置設定、增強或固定資料版本會重新比對。這不等於即時 GPU 效能量測，背景負載仍會改變速度。

Ultralytics 使用 `on_train_epoch_start`、`on_train_batch_end`、`on_train_epoch_end`、`on_fit_epoch_end` 與驗證 callback。已安裝版本的 trainer 在最後另有內部驗證，這段也單獨記錄；它不會被當成多完成一個 Epoch，也不宣稱 all-train 的內部檢查是獨立評估。原生 TorchVision 使用相同計時入口；像素基準改用原圖數與門檻搜尋次數。

方法參考：[tqdm 速度與平滑參數](https://tqdm.github.io/docs/tqdm/)、[指數平滑](https://otexts.com/fpp3/ses.html)。平滑不會讓未來耗時變成確定值；回放採用逐步向前評估，預測時不讀取後續耗時。

## 不確定性與停滯

- 畫面可顯示「波動範圍」。它由近期耗時對估計值的偏差與保守下限建立，**不是經校準的 95% 信賴／預測區間**。
- 少於 4 個樣本時保留較寬範圍；歷史初估也保留至少 30% 的波動幅度。
- 超過預期回報間隔時改顯示目前階段與已用時，不繼續倒數或保留過期範圍。
- 至少有 4 個先前樣本，且單位耗時超過 `max(30 秒, 近期中位數 × 8)`，便保留實際已用時與完成量，但重建速度估計。這是異常間隔偵測，無法僅靠時間區分電腦休眠與真正耗時暴增；若後續持續緩慢，新的樣本會建立較慢速度。
- 含異常間隔的階段不作為未來工作的歷史速度。早停、失敗與停止不會被顯示為預定輪數全部完成；ETA 不預測早停發生時刻。

## 保存與相容性

Run 狀態增加 `timing`、`timing_profile`、`timing_plan`、`timing_prior`、`timing_match_key` 與 `time_estimate`。狀態事件與可更新快照會一起保留最新計時資料；讀取快照時也會合併最新 Batch 的 timing 欄位。記憶體樣本有界，不逐 Batch 累積完整陣列。

舊 Run 缺少新計時紀錄時仍可顯示原本狀態，但不捏造歷史耗時。舊事件可用於離線回放比較；不會自動把混合階段的舊 Epoch 時間轉成新分階段資料。沒有資料庫遷移或使用者歷史改寫。

主程式與兩種獨立模型環境均固定 tqdm 依賴；元件檢查會確認模型環境可匯入 tqdm。Headless adapter 使用 tqdm 的計數與時鐘欄位，因此升級 tqdm 時必須執行時鐘、停滯及 callback 回放測試。

## 驗證結果與限制

驗證只執行單元測試、callback 回放、Qt 桌面隔離測試及既有事件唯讀回放。沒有執行新訓練、反向傳播或效能探測。

合成資料各 80 個單位；前 3 次為快速初估，從第 4 次起計算剩餘時間平均絕對誤差（MAE）。比較基準為當次工作累計平均速度，並非舊介面的加權百分比算法。

| 合成情境 | 本版 MAE（秒） | 累計平均 MAE（秒） |
| --- | ---: | ---: |
| 固定速度 | 0.00 | 0.00 |
| 隨機波動 | 7.54 | 5.20 |
| 首個單位較慢 | 10.82 | 41.11 |
| 中途變慢 | 41.73 | 54.69 |
| 中途變快 | 41.73 | 54.69 |

冷啟動與速度變化情境改善；單純隨機波動情境中，累計平均較好。未發生的速度突變仍不可預知，表格包括突變前的預測誤差。

本機 4 組既有事件按匿名順序回放，單位是「完整 Epoch 間隔，含驗證」，不能視為新 Batch callback 的實際 GPU 驗收：

| 歷史組別 | 間隔數 | 加權絕對百分比誤差 | 說明 |
| --- | ---: | ---: | --- |
| A | 15 | 0.72% | 一般間隔 |
| B | 49 | 1.81% | 一般間隔 |
| C | 79 | 97.35% | 含約 53,793 秒異常間隔，突發長停頓無法事先預知；間隔後重建速度 |
| D | 79 | 4.46% | 一般間隔 |

異常間隔當次暫停輸出數值，其餘預測仍全部納入，包括停頓前預測；不刪除異常序列來美化結果。這些是開發回放，並非外部保留資料的保證精度。測得估算器單次更新約 0.02–0.04 ms，不含既有事件／檔案寫入成本，也不是 UI/API 延遲保證。
