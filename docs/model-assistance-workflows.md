# AI 輔助標註與模型試跑

這兩類功能刻意放在不同流程，避免把「協助製作標註」和「檢查已訓練模型」混為一談。

## 流程 03：標註編輯

### SAM2 互動分割

- 使用 SAM2 官方預訓練權重，不依賴本專案先完成訓練。
- 使用者用前景點、背景點或提示框指定目標，系統產生候選遮罩。
- 候選只會在使用者按下接受後加入目前標註。
- GrabCut 是不使用神經網路的 CPU 備用工具。

### 專案模型自動標註

- 使用流程 06 已完成訓練，或流程 07 匯入且具推論介面的模型。
- 一次只替目前編輯圖片建立候選，避免不透明的整批覆寫。
- 黃色候選可先預覽；接受後才加入標註並回到待審狀態。
- 候選採附加方式，不會直接取代人工標註。

## 流程 07：評估與模型

### 匯入外部 YOLO／RT-DETR 模型

按右上角「匯入模型」，選擇本機 `.pt` 檔案，輸入選填的顯示名稱並確認來源可信任，再按「驗證並匯入」。瀏覽器模式也可直接填入執行工作台電腦上的完整路徑。

- 先至「設定 → 模型與元件」安裝 Ultralytics 執行環境。
- 支援該環境能載入的 Ultralytics YOLO 物件偵測／實例分割與 RT-DETR 偵測 checkpoint；不接受只有 state_dict 的任意 PyTorch 權重、ONNX、分類、姿態或 OBB 模型。
- `.pt` 反序列化可能執行 Python 程式碼，僅載入自己訓練或信任來源的檔案。獨立 worker 用於隔離執行生命週期，不是安全沙箱。
- 系統先複製權重，再驗證架構、連續類別索引及一次 CPU 推論；通過後才建立 M 系列模型版本。失敗會清除未完成副本。
- 保留來源檔名、SHA-256、架構與類別；原始檔移走後仍可使用專案中的副本。
- 模型顯示「外部匯入／尚未評估」，不建立虛假的 Run、資料版本或評估分數。CPU 推論驗證不代表已量測模型準確率。
- 匯入後可使用圖片／影片試跑與模型封裝匯出。預標註前須在專案管理類別中建立與模型相同的類別名稱，避免類別對應錯誤；不會自動改名或覆寫既有類別。
- 外部模型尚未綁定本專案固定資料版本，因此不提供 Test／Validation 比對；本次也不提供外部權重續訓。

可載入的版本由本機 Ultralytics 環境決定；官方介面見 [Python 使用指南](https://docs.ultralytics.com/usage/python) 與 [RT-DETR](https://docs.ultralytics.com/models/rtdetr)。

### 「備份與外部交換」的用途

此入口用於匯出已核准的圖片與標註，保留資料版本或提供給外部工具。可選工作台原生格式、COCO、YOLO 偵測／分割、LabelMe、分類資料夾與 JSONL；先驗證格式，再建立匯出版本。它不是整套工作台、執行環境與所有模型的完整備份。模型權重請使用模型詳細頁的「匯出模型封裝」或上述「匯入模型」。

### 儲存與升級

遷移 0005 允許外部模型、其匯出與預標註紀錄沒有本機 Run／資料版本關聯，保留既有模型與外鍵。既有資料庫升級前沿用遷移備份機制，產生 `.before-migration-0005.backup`；原模型 manifest 與 checkpoint 不會改寫。

### 外部圖片／影片試跑

- 輸入專案外圖片或一支影片，資料只讀取到暫存工作階段，不匯入專案。
- 影片會解碼並推論每一個影格，不預設抽幀、跳幀或限制影格數。
- 同一個試跑工作只載入模型一次。
- 使用者可播放影片結果、逐幀檢查並調整顯示信心門檻。
- 外部資料若沒有人工標註，只能觀察預測位置、類別、信心與推論結果；不能宣稱 Precision、Recall 或 mAP。
- 暫存結果在桌面程式關閉時清除。

### 已標註資料比對

- 使用模型所屬固定資料版本中的 Test 或 Validation 圖片重新推論。
- 藍色虛線表示人工標註，綠色表示模型預測。
- 以相同類別及 Box IoU 0.50 進行一對一配對，顯示 TP、FP、FN、Precision 與 Recall。
- 調整信心門檻時，畫面與上述指標同步重算。
- 這是特定信心門檻下的錯誤分析，不等同於跨多個 IoU 門檻彙整的 mAP50–95。

## 執行與失敗條件

- 試跑只對「已安裝推論環境、且引擎有推論介面」的模型開放；未安裝時按鈕停用。
- 工作在模型所屬的獨立元件環境執行，並沿用 GPU 資源鎖。
- 未知總工期時不顯示百分比或以計數假裝進度；只有取得足夠、持續更新的真實進度樣本時才顯示剩餘時間估算。
- 影片逐幀處理可能產生大量暫存影格，磁碟不足或影片無法解碼時工作會明確失敗，不會改動專案資料。
