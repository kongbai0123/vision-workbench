# AI 輔助標註與模型試跑

這兩類功能刻意放在不同流程，避免把「協助製作標註」和「檢查已訓練模型」混為一談。

## 流程 03：標註編輯

右側欄頂部的「新物件類別」將專案類別顯示為按鈕，點一下就能選擇後續新增物件使用的類別。選好類別後，按畫布工具列的「新增矩形框（R）」即可在畫布上拖曳新增。按「選取／編輯（V）」後，可以拖曳移動既有框或調整大小，並在「物件」頁籤的詳情更改類別。「AI 輔助」下方可切換「互動分割」「批量找框」與「模型預標註」。

按下「產生」或「開始」後，工作台在 03 內切到整頁「AI 訊息」。畫布沿用目前影像，右側顯示對應工具的進度、候選與處置操作。按「返回標註編輯」可在原圖修框，標註頁上方的「AI 訊息」可再次開啟結果。

### 依類別批量找框（MM ＋ Qwen）

1. 在內建標註編輯器開啟「AI 輔助 → 批量找框」，選目前影像或左側清單篩出的影像，再勾選本批使用的類別。每個類別可填 MM 的英文找框詞和 Qwen 的判讀規則。
2. 按「開始批量找框」。AI 訊息頁可看處理階段、停止作業、選擇批次影像和切換已完成的批次。模型先提出候選、判讀類別與框的範圍，並記錄疑點和局部重查原因。
3. 點候選看原圖疊框和裁決。即使第一個框已經正確，也須按「採用到畫布」確認。採用後成為人工確認的標註，可在同一畫布拖曳修框或改類別，也可以直接補框。與採用框高度重疊的候選會移到「已處理的候選」，保留模型結果和原座標供比較。其餘物件可繼續核對。
4. 對照整張圖後按「確認例外已處理」，可再前往下一筆例外。從「04 資料審核」也可回到相同影像。整張的正式核准沿用「04 資料審核」。

MM 與 Qwen 使用本機權重，推論在 Windows 的斷網 AppContainer 內執行。建議採用的框需有 MM 分數至少 0.35，且 Qwen 兩種選項順序都判為符合。兩次附帶的選項總權重都須至少 0.50，前兩名分差至少 0.20。低於建議門檻的候選可留待人工覆核。這些是模型的支持值，實際精確率需用獨立人工標註評估。

若特定類別缺乏可靠候選，AI 訊息會請使用者確認圖中是否有該類別，並提供「框選 CLS」入口。補框並儲存後，可從結果對目前影像與類別選「以人工範例重跑」，或在批量找框勾選「使用已確認的人工範例」。

重跑會從專案內符合資格且已儲存的人工框中，挑選至少兩個獨立來源的同類裁圖，由 Qwen 產生視覺描述輔助找框。模型權重與建議門檻固定。範例會排除本批目標及其來源群組，已保留的驗證／測試資料及同群組影像也排除於範例和重跑範圍。目標圖的既有人工框用於去重和保護原標註。範例不足或描述無法確認的類別保留待人工處理。每次重跑的候選仍須由人工採用。

- **SAM 2.1 框界檢查**使用候選框提示分割，最多檢查每張 6 個 Qwen 建議採用或待覆核的候選。畫布可分別顯示 MM 原始框和 SAM 遮罩外接框。兩框 IoU 低於 0.75 或無法可靠分割的候選會列出覆核原因。兩框重疊程度只衡量模型間框界一致性。
- **Gemma 4 觀察覆核**可在批次設定另外開啟。它在同一個斷網 AppContainer 內獨立覆核抽查的原始候選，畫面顯示與 Qwen 的一致或分歧、兩次判讀與健全性檢查結果。Gemma 的輸出只供觀察。

本機元件存放在 Vision Workbench 程式根目錄下的 `models/annotation-assist/`，需包含 `runtime/`（獨立 Python、CUDA 版 PyTorch、Transformers、Pillow 與 Safetensors）、`MM-Grounding-DINO-Tiny/`（含 `health/` 健全性檢查圖）和 `Qwen3-VL-4B-Instruct/`（含權重來源清冊）。可以用 `VISION_WORKBENCH_ANNOTATION_ASSIST_HOME` 指定另一個已備妥的本機目錄，相對值以程式根目錄為基準。執行時會驗證權重版本與網路隔離。

開啟框界檢查另需 `sam2.1-hiera-tiny/`。開啟觀察覆核另需 `Gemma-4-E4B-it-QAT-Q4/` 的權重和視覺投影器，以及 `_runtimes/llama.cpp-b12541-cuda13.5/` 的本機執行庫。

換電腦時，把已備妥的 `models/annotation-assist` 資料夾放到新電腦可讀取的位置，例如 USB 隨身碟。在新電腦開啟「設定 → 模型與元件」，選擇「從資料夾安裝批量模型」並指定該資料夾。安裝會將該版本使用的元件複製到新 Workbench 的 `models/annotation-assist/`。若有指定自訂位置，請將已備妥的套件放到該位置。設定頁顯示檔案檢查狀態，實際推論仍需要相容的 NVIDIA GPU、驅動程式，以及通過 Workbench 的權重與執行環境檢查。

### SAM2 互動分割

- 使用 SAM2 官方預訓練權重，不依賴本專案先完成訓練。
- 使用者用前景點、背景點或提示框指定目標，系統產生候選遮罩。
- 候選只會在使用者按下接受後加入目前標註。
- GrabCut 是不使用神經網路的 CPU 備用工具。

### 專案模型預標註

- 使用流程 06 已完成訓練，或流程 07 匯入且具推論介面的模型。
- 一次只替目前編輯圖片建立候選，避免不透明的整批覆寫。
- 黃色候選可先預覽；接受後才加入標註並回到待審狀態。
- 候選採附加方式，不會直接取代人工標註。

## 流程 07：評估與模型

### 匯入外部 YOLO／RT-DETR 模型

按右上角「匯入模型」，把一個 `.pt` 檔案拖入上傳區（桌面版可直接從檔案總管拖入），或點擊上傳區開啟系統檔案瀏覽器；輸入選填的顯示名稱並確認來源可信任，再按「驗證並匯入」。桌面版與瀏覽器模式都不需要手動輸入完整路徑。

- 先至「設定 → 模型與元件」安裝 Ultralytics 執行環境。
- 按下「驗證並匯入」後會先刷新執行環境狀態；元件不可用時不會開始上傳大型權重檔。
- 支援該環境能載入的 Ultralytics YOLO 物件偵測／實例分割與 RT-DETR 偵測 checkpoint；不接受只有 state_dict 的任意 PyTorch 權重、ONNX、分類、姿態或 OBB 模型。
- `.pt` 反序列化可能執行 Python 程式碼，僅載入自己訓練或信任來源的檔案。獨立 worker 用於隔離執行生命週期，不是安全沙箱。
- 瀏覽器選到的檔案會串流至本機工作台的一次性暫存區，不會送到外部服務；匯入工作領取後代碼立即失效，成功或失敗都會刪除暫存副本。
- 桌面版拖入的檔案由視窗層取得原始路徑，直接複製匯入而不經過暫存區；原始檔案保留在原位置。
- 系統先複製權重，再驗證架構、連續類別索引及一次 CPU 推論；通過後才建立 M 系列模型版本。失敗會清除未完成副本。
- 保留來源檔名、SHA-256、架構與類別；原始檔移走後仍可使用專案中的副本。
- 模型顯示「外部匯入／尚未評估」，不建立虛假的 Run、資料版本或評估分數。CPU 推論驗證不代表已量測模型準確率。
- 匯入後可使用圖片／影片試跑與模型封裝匯出。預標註前須在專案管理類別中建立與模型相同的類別名稱，避免類別對應錯誤；不會自動改名或覆寫既有類別。
- 外部模型尚未綁定本專案固定資料版本，因此不提供 Test／Validation 比對；本次也不提供外部權重續訓。

可載入的版本由本機 Ultralytics 環境決定；官方介面見 [Python 使用指南](https://docs.ultralytics.com/usage/python) 與 [RT-DETR](https://docs.ultralytics.com/models/rtdetr)。

### 「備份與外部交換」的用途

此入口用於匯出已核准的圖片與標註，保留資料版本或提供給外部工具。可選工作台原生格式、COCO、YOLO 偵測／分割、LabelMe、分類資料夾與 JSONL；先驗證格式，再建立匯出版本。它不是整套工作台、執行環境與所有模型的完整備份。模型權重請使用模型詳細頁的「匯出模型封裝」或上述「匯入模型」。

### 儲存與升級

遷移 0005 允許外部模型、其匯出與預標註紀錄沒有本機 Run／資料版本關聯，保留既有模型與外鍵。既有資料庫升級前沿用遷移備份機制，產生 `.before-migration-0005.backup`；原模型 manifest 與 checkpoint 不會改寫。

### 選擇要使用的模型版本

- 模型試跑、標註比對與模型匯出共用同一個「目前選定的模型版本」。
- 可從左側「模型版本」清單點選（選定的那一列標示「使用中」），或直接在「模型試跑」的「試跑模型」與「標註比對評估」的「比對模型」下拉選單切換；三者永遠同步。
- 篩選或搜尋若把目前選定的版本隱藏，選取會自動落到第一個可見版本，兩個下拉選單會同步顯示新的選取。
- 試跑與比對的狀態訊息都會寫出實際使用的模型版本 ID。

### 外部圖片／影片試跑

- 輸入專案外圖片或一支影片，資料只讀取到暫存工作階段，不匯入專案。
- 影片會解碼並推論每一個影格，不預設抽幀、跳幀或限制影格數。
- 同一個試跑工作只載入模型一次。
- 使用者可播放影片結果、逐幀檢查並調整顯示信心門檻。
- 預測類別與信心標籤以畫面像素繪製，字體不低於 12px；靠近影像邊緣時會自動調整位置，避免遭裁切。
- 外部資料若沒有人工標註，只能觀察預測位置、類別、信心與推論結果；不能宣稱 Precision、Recall 或 mAP。
- 結果上方固定標示產生它的模型版本；之後若改選其他版本，會提示畫面上的結果來自哪一個版本，必須重新執行才會換。
- 暫存結果在桌面程式關閉時清除。

### 已標註資料比對

- 使用模型所屬固定資料版本中的 Test 或 Validation 圖片重新推論。
- 藍色虛線表示人工標註，綠色表示模型預測。
- 以相同類別及 Box IoU 0.50 進行一對一配對，顯示 TP、FP、FN、Precision 與 Recall。
- 調整信心門檻時，畫面與上述指標同步重算。
- 這是特定信心門檻下的錯誤分析，不等同於跨多個 IoU 門檻彙整的 mAP50–95。

## 執行與失敗條件

- 試跑只對「已安裝推論環境、且引擎有推論介面」的模型開放；未安裝時按鈕停用。
- 工作在模型所屬的獨立元件環境執行，並沿用 GPU 資源鎖。
- 未知總工期時不顯示百分比或以計數假裝進度；只有取得足夠、持續更新的真實進度樣本時才顯示剩餘時間估算。
- 影片逐幀處理可能產生大量暫存影格，磁碟不足或影片無法解碼時工作會明確失敗，不會改動專案資料。
