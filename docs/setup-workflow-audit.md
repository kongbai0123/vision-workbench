# 04–06 設定流程與資料儲存

[返回 README](../README.md) · 版本 2.19.0 · 2026-09-24

本輪驗證到「04 資料審核 → 05 資料準備 → 06 訓練設定」為止。使用隔離測試專案，桌面測試封鎖訓練入口；沒有啟動真實訓練、下載權重或修改既有使用者專案。通過設定檢查不代表已驗證 GPU 記憶體、訓練效能或模型精度。

## 設定如何生效

1. **04 審核**：只有已核准影像進入資料準備；修改標註後回到待審核。先前固定的資料版本仍保留原始內容。
2. **05 草稿**：設定分割與增強。增強參數按專案保存，分割管理器重開時恢復最後已套用方案；尚未套用的分割預覽不是正式分割。
3. **固定版本**：建立 Dxxx，凍結該次專案修訂、分割、類別、標註、影像雜湊與增強配方。畫面修訂過期則要求重新整理，避免固定非預期版本。
4. **06 選擇版本及引擎**：使用選定 Dxxx 的配方，切換模型保留各自參數。05 草稿與該版本不同時顯示提示，不能把修改草稿誤認為已更新 Dxxx。
5. **驗證設定（不訓練）**：檢查參數 schema、資料分割、引擎相容性、manifest 與圖片 SHA-256；顯示輸入量、批次及環境狀態。修改設定後舊驗證結果失效。此操作不建立 Run、不開始訓練。

草稿允許保存輸入到一半的文字，方便接續編輯；非法值會阻擋固定版本或相關設定操作。多視窗發生版本衝突時拒絕覆蓋，保留畫面輸入並提示重新載入方式。

## 數量與支援範圍

例如 100 張原圖分成 Train 60、Validation 20、Test 20，每張 Train 原圖額外擴充 2 次：

| 項目 | 原圖 | 額外載入 | 用途中的輸入量 |
| --- | ---: | ---: | ---: |
| Train | 60 | 120 | 每輪 180 |
| Validation | 20 | 0 | 評估 20 |
| Test | 20 | 0 | 評估 20 |

原始資料仍是 100 張，不會重新分割 220 張不同原圖。額外載入是同一 Train 原圖的隨機增強事件，可能相似或重複，不能宣稱成為統計獨立的新樣本。Validation／Test adapter 即使收到增強配方也不擴充。

| 引擎 | 計數與限制 |
| --- | --- |
| Ultralytics YOLO／RT-DETR | 依固定配方準備 Train 額外載入項目；包含原始載入項目的所有 Train 輸入都可能被增強。對比欄位不直接傳入；RT-DETR 最終變換依安裝的 adapter，設定檢查不等同實際跑過所有變換。 |
| 原生 TorchVision 偵測／分割／分類 | 使用擴充槽位，支援亮度、對比、水平／垂直翻轉；不支援的非零幾何或混合增強會列在驗證摘要。 |
| 內建像素基準 | 讀取 Train 原圖建立統計，不使用擴充、Batch 或梯度累積；摘要不再顯示未採用的增強數量。輪數對應 Validation 門檻搜尋。 |

「設定有效批次」為 Batch × 梯度累積，最後不足一批、Ultralytics 暖身期與實際資料量可能使執行批次不同；不是 GPU 執行結果。原生 SGD 現在明確傳入介面描述的 momentum 0.9。

## 資料權威來源與儲存安排

沿用本機產品適用的商用資料管理原則：分層儲存、唯一權威來源、交易、修訂衝突、不可變產物與可追溯歷史。本版沒有引入分散式服務，也沒有宣稱已完成大型多人部署的容量驗證。

| 資料 | 權威來源 | 更新規則 |
| --- | --- | --- |
| 影像資訊、標註、審核、分割 | 每專案 `project.sqlite3` | SQLite 交易；內容修訂與標註修訂分開，歷史以標註雜湊引用內容 |
| 05／06 可編輯設定 | `workflow_drafts` | schema 版本、獨立 revision、比較版本後更新；不讓改參數污染資料集內容修訂 |
| 設定變更紀錄 | `workflow_draft_history` | 與目前草稿同一交易追加，主鍵為 scope + revision；相同內容不重複寫入 |
| 原始影像 | 專案 `images/` | 內容雜湊命名、不可變檔案；匯入、刪除與版本發布協調圖片鎖 |
| 固定資料集 | `datasets/Dxxx/manifest.json` 及版本圖片 | 先寫暫存目錄，再原子發布；manifest 記錄配方、split、來源修訂及 SHA-256。圖片使用硬連結或複製保存 |
| 訓練與模型產物 | `runs/`、`models/` | 執行流程才會建立；本輪設定驗證不產生 Run／模型。既有執行事件與控制紀錄規則延續原架構 |
| 清單與快速摘要 | SQLite artifact catalog／摘要快取 | 可重建查詢索引，不能反向改寫固定版本 |

新增 migration `0006_workflow_drafts.sql`。啟動升級沿用 SQLite backup API 備份已提交的 WAL 內容，再逐版交易遷移；失敗回滾。資料庫沿用 WAL、外鍵及 FULL 同步。JSON 草稿限制 64 KiB，固定 scope 與允許欄位，模型參數保留原始輸入字串並於使用前做領域驗證。

版本發布使用專案發布鎖、圖片鎖及一致的專案快照：readiness 與 manifest 來自同一修訂；兩個同時發布要求不會取得相同 Dxxx。影像與設定分開存放，避免把大檔塞入交易表。資料目錄結構維持相容，沒有搬移使用者既有原圖。

草稿歷史目前保留全部已提交修訂；長期大量編輯的保留政策、離機備份、多人授權與分散式物件儲存屬於後續容量及部署工作，不在這輪驗證範圍。
