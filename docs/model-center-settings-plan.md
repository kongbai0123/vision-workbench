| MODEL-02 | 語意分割 | DeepLabV3 MobileNet V3、ResNet50 | 原生遮罩派生 class map；同類合併、異類重疊及未標區域策略明確；mIoU、Dice |
| MODEL-03 | 影像分類 | MobileNet V3、EfficientNet-B0、ResNet18 | 新增圖片層級分類與審核；Macro F1、各類召回率、混淆矩陣 |

## 2. 模型目錄與本機狀態

建立單一模型目錄供訓練頁和設定中心使用。目錄可離線閱讀，不能只根據已安裝套件產生清單。

- 顯示模型名稱、任務、用途、所需標註、變體、可用能力、來源及授權。
- 提供搜尋及「全部／本機可用／尚待安裝／符合目前任務」篩選。
- 訓練頁優先顯示符合當前任務的模型，提供「查看所有模型」；未安裝選項仍可選取以查看說明。
- 已安裝程式套件、預訓練權重與使用者訓練出的 ModelVersion 分別管理。
- 硬體建議需綁定變體、輸入尺寸、batch size 與精度；無實測資料就標示待測，不能只依模型名稱給固定顯存承諾。

狀態需分成數個面向，不應只有 `installed: true/false`：

| 面向 | 狀態例子 | 呈現／操作 |
| --- | --- | --- |
| 工作台整合 | 已支援／規劃中 | 未完成 adapter 的項目標示規劃中，不能提供假的「安裝即可使用」 |
| 執行環境 | 未安裝／排隊／安裝中／待驗證／可用／需修復／不相容 | 安裝、查看進度、重新檢查、修復或查看原因 |
| 預訓練權重 | 未下載／下載中／已驗證／損壞 | 下載、選擇受支援本機權重、重新下載；支援從零訓練者另列選項 |
| 專案資料 | 相容／缺少標籤／需轉換／轉換有損 | 跳轉補標、檢視轉換報告；安裝模型不等於資料已合格 |
| 目前操作 | 可開始／資源占用／缺少條件 | 清楚說明為何無法開始，不默默改成其他引擎 |

選單保留使用者選擇；安裝後刷新狀態，不應重設資料版本、參數或自動切換模型。

## 3. 選用及安裝流程

1. 使用者在訓練頁選擇模型，旁邊顯示用途與本機準備狀態。
2. 缺少環境時顯示行內提示：「此模型尚未準備完成。安裝必要元件後即可用於訓練。」提供「查看安裝方案」與可用替代方案。
3. 打開設定中心的對應模型詳情，保留訓練頁內容。
4. 顯示即將安裝的共用元件、所選權重、來源、版本、已知下載量、磁碟需求及 CPU／GPU 建議；未知大小需明示。
5. 使用者按「安裝必要元件」後才下載。預設只準備該模型需要的元件及選定權重，不一次下載所有模型。
6. 在背景工作列顯示「準備環境 → 下載 → 安裝 → 驗證」階段；提供日誌、失敗原因、重試及安全取消。不能安全即時取消的階段明確顯示「等待此步驟完成」。
7. 通過環境、模型載入及小型推論檢查後，顯示「已可用」和「返回訓練」。訓練仍需使用者另外啟動。

關閉設定面板不取消安裝；重新打開可接續查看。關閉整個工作台時要顯示安裝是否會繼續的實際行為；重開後回收工作狀態，不能永久卡在安裝中。

套件相容者共用版本化環境與下載快取，相容性不同者使用獨立環境。安裝／修復不直接升級桌面版所使用的 PySide6，也不覆寫正在訓練使用的環境。

移除元件前列出共用引用。移除 runtime 或預訓練快取不得刪除原圖、標註、資料版本、Run 或使用者模型；仍被引用的環境需保留或先完成可重現遷移。

## 4. 設定中心建議版型

右上角入口改成「設定」，開啟沿用工作台深色樣式的寬側欄。側欄約 960px、最大不超過視窗寬度；小視窗使用全寬面板。左邊分類導覽，右邊設定內容，頂部固定標題及關閉按鈕，底部顯示背景工作。

| 分類 | 內容 | 第一階段範圍 |
| --- | --- | --- |
| 一般 | 介面縮放、啟動與離開行為、設定適用範圍 | 只呈現真正有實作的設定 |
| 模型與元件 | 模型清單、用途、安裝、權重、版本、檢查、修復、移除 | 核心交付；既有 SAM2 可作為標註輔助元件分組 |
| 運算與儲存 | GPU／CPU 狀態、預設裝置、磁碟及快取資訊 | 先提供檢查及預設值；資料搬移另走驗證過的流程 |
| 編輯器 | 內建／Labelme／CVAT 預設值、狀態、連線檢查及同步設定 | 沿用既有整合入口，不另開一套標註資料來源 |
| 更新 | 程式版本、更新說明、依賴變更、元件更新、重新啟動 | 區分本機程式變更與正式版本更新 |
| 診斷與關於 | 系統摘要、環境檢查、安裝／訓練日誌、版本與授權 | 可複製診斷摘要；避免混入憑證及圖片內容 |

訓練頁只處理「本次 Run 的模型、資料及參數」；設定中心管理「這台電腦的元件、預設值與環境」。新預設只套用新建工作，不改寫既有 Run。專案類別、審核與資料分割維持專案範圍。

模型條目用「名稱＋用途＋狀態＋操作」列式呈現，可展開詳情；不要把所有安裝技術欄位塞入訓練表單。模型元件與「評估與模型」中的已訓練模型清楚區分。

Web 介面共用設定 UI。桌面檔案／安裝／重新啟動等操作由本機服務與必要的 native bridge 執行，不能讓新 API 繞過既有本機驗證與來源限制。瀏覽器模式對不支援的動作需說明原因及桌面入口。

## 5. 更新行為

- 「工作台版本」、「模型元件」與「預訓練權重」分開檢查及更新。
- 現行更新器只比較啟動時與現在的本機原始碼，不能顯示成已檢查 GitHub 最新發布版；正式線上更新是獨立待辦。
- 更新前顯示變更及缺少的依賴；需要補環境時能連到安裝中心，不能只要求使用者手動執行 bootstrap。
- 下載／準備與啟用分開；衝突時等訓練、推論、安裝或標註同步完成後再切換版本。
- 更新重啟前保存標註、完成同步；失敗保留原版本及可追查原因。
- 正式版更新使用發布資產及驗證流程；一般使用者安裝模型或更新程式不應走開發者 git push 登入流程。
- 元件版本與權重雜湊記入 Run／ModelVersion；不能因全域更新破壞舊模型重現與推論。

## 6. 資料及模型整合約束

- 持續以已核准 DatasetVersion 為訓練來源。資料適配由背景程序完成，允許建立受管理的派生快取；使用者不必手動匯出再匯入。
- 框由遮罩的有效像素邊界推導；全圖遮罩儲存尺寸不等於物件 bbox。
- 語意分割對不同類別重疊、前景與部位階層、background／ignore label 有明確策略，不能任意覆蓋。未標註區域不自動視為已確認背景。
- 分類建立圖片標籤及修訂；異常檢測建立正常／異常／未知狀態，不能把「沒有畫框」直接當正常。驗證／測試資料必須適合計算所宣告指標。
- YOLO 標準 segmentation 格式使用 polygon；RLE 的孔洞、多個連通區與細邊界可能在轉換中改變。比對回轉 mask、揭露誤差、必要時阻擋或使用已驗證的原生 mask loader，不能聲稱無損。
- 偵測框、實例遮罩、語意區域、分類分數、異常熱圖分別定義輸出。熱圖經門檻產生的區域保留模型與門檻來源；未經人工分類的異常區域不能假冒已知缺陷類別。
- 所有接受的預測產生新的待審修訂。三編輯器與審核共用修訂；圖片層級標籤在工作台提供共用控件，外部編輯器不支援的資料應保存且避免讀回時抹除。
- 每模型逐項驗證訓練、評估、推論、checkpoint 保存及部署格式；只完成 checkpoint 保存不能標示已支援 ONNX／TensorRT。
- PatchCore 等方法需呈現建模／特徵庫進度，不把不適用的 epoch／learning rate 強加到全部模型。

現行實作需要特別修正的接點：

- `web/app.mjs` 的 `renderTraining` 停用未安裝選項並自動選另一可用模型。
- `workbench/training.py` 以 package 檔案存在作為 Torch 檢查捷徑，且啟動後快取結果；需完整健檢及安裝後刷新。
- `workbench/desktop.py` 的 `open_settings` 僅提供更新；`apply_update` 要納入 TrainingWorkspace 的活動工作。
- `workbench/desktop_update.py` 的監測來源不含 `requirements-training.txt`；依賴檢查需依各 runtime manifest 分開執行。
- `bootstrap.ps1` 可保留命令列安裝入口，但應與 UI 安裝器共用固定元件定義，避免兩套版本來源。
