## 選配元件

先依 [快速開始](../README.md#快速開始) 安裝主程式，再依工作需求準備元件。環境與權重首次安裝需網路；準備完成後可在本機執行。

| 元件 | 用途 | 準備方式 |
| --- | --- | --- |
| Labelme | 嵌入式標註編輯 | 隨主程式安裝 |
| GrabCut | 傳統影像分割 | 隨主程式提供 |
| SAM2 | AI 輔助分割 | 執行下方 AI 安裝指令 |
| TorchVision | Mask R-CNN、Faster R-CNN、DeepLabV3、圖片分類 | 設定中的模型與元件，或下方訓練環境指令 |
| Ultralytics | RT-DETR、YOLO26 Detect／Seg | 設定 → 模型與元件 → 安裝必要元件 |
| CVAT | 本機網頁標註編輯 | 在編輯器選擇 CVAT，依安裝引導準備 WSL 2 與 Docker |

SAM2：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\bootstrap.ps1 -AI
```

TorchVision：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\bootstrap.ps1 -Training
```

TorchVision 使用 `.venv-training`；Ultralytics 使用 `.venv-models/ultralytics`。GPU 加速需要相容的 NVIDIA GPU 與驅動程式；是否可用以設定頁檢查結果為準。相機採集需要 Windows 可辨識的影像裝置。

YOLO26 Detect／Seg 預設使用預訓練權重微調，也可選擇隨機初始化；首次訓練可能下載權重。Detect 將矩形或面積標註轉為緊密框，不執行 Seg 的多邊形孔洞相容檢查。RT-DETR 目前從隨機權重開始訓練。Ultralytics 元件使用 AGPL-3.0 或 Enterprise 授權，請查閱安裝頁說明。

EfficientAD／PatchCore 目前列為規劃項目，尚未開放安裝與訓練。

## 專案流程

1. 建立專案、設定物件類別，加入圖片或採集影像。
2. 在內建編輯器、Labelme 或 CVAT 建立及修改標註。
3. 到「資料審核」確認標註並核准圖片。
4. 在「資料分割」預覽來源群組及類別分布，套用 Train／Validation／Test 分配。
5. 在「模型訓練」建立固定資料版本、設定模型與參數並開始訓練。
6. 到「評估與模型」檢查結果、匯出模型或產生預標註候選。

三個編輯器共用專案圖片與標註；切換時會等待儲存及同步完成。修改已核准標註後，圖片會回到待審核。模型輸出先保存為候選，使用者接受後加入標註，再進入人工審核。

Labelme 嵌入功能需要桌面版。CVAT 尚未支援的影片軌跡、整張標籤或形狀會阻擋同步；發生版本衝突時，先處理衝突再切換編輯器。

## 資料分割

智慧分割依拍攝批次、影片來源及相同圖片 SHA-256 建立群組，再平衡類別與集合比例。可鎖定群組、保留目前 Test，或手動定義獨立來源。此功能使用來源資訊及標註統計，未使用影像特徵辨識近似圖片。

Train 與 Validation 都須涵蓋所有已有標註的類別。若類別只有一個來源群組，需補充獨立來源才能同時訓練與驗證。Test 可選；不足的類別會標示為評估限制。

固定資料版本保存建立當時的圖片、標註及分割。修改專案後，需建立新資料版本才會用於後續訓練。既有版本可繼續用於重現及比較實驗。版本影像會在同一磁碟以 hard link 共用經雜湊驗證的不可變原圖；不支援時自動使用獨立副本。

流程驗證副本允許以同拍攝來源的時間區段測試訓練流程，但評估會標示來源不獨立；其分數不能代表新場景表現。

## 訓練與評估

- 模型參數依引擎提供影像尺寸、批次大小、學習率、最佳化器及排程；設定保存於每次 Run。
- Validation 用於選模、門檻搜尋或訓練控制；Test 僅用於最後評估。未提供 Test 時，結果顯示尚未執行。
- 訓練頁可勾選已完成模型疊圖比較。不同定義的指標不會直接疊在一起；缺失 Epoch 會保留缺口。
- Macro IoU 是各類別在整個集合累積像素交集／聯集後的平均；Micro IoU 則合計所有類別的像素再計算。真值與預測均空白的類別顯示 N/A。
- 信心分數、Mask IoU 與 mAP 衡量不同性質；精細輪廓仍應以原圖上的真值與預測比對。
- 評估來源記錄權重選擇方式與 Test 來源是否重疊。模型比較需使用相同資料版本及評估定義。

## YOLO Seg 相容性

在資料審核階段檢查遮罩相容性；啟動 YOLO Seg 訓練時會再次檢查固定資料版本。問題清單提供圖片、類別與孔洞位置，可開啟放大預覽。

- **修補微小封閉孔洞**：依單孔大小、總像素、相對面積及寬高門檻產生訓練相容副本；實際門檻以模型參數為準。
- **嚴格無損**：無法精確轉為多邊形時阻擋訓練。

相容處理只寫入 Run 的 YOLO 資料副本，並保存轉換報告。超過門檻的孔洞及分離區塊需人工處理，或使用能讀取原生遮罩的模型。

## 支援格式

| 格式 | 匯入 | 匯出 |
| --- | :---: | :---: |
| Vision Workbench 原生格式 | ✓ | ✓ |
| COCO | ✓ | ✓ |
| YOLO Detection／Segmentation | ✓ | ✓ |
| LabelMe | ✓ | ✓ |
| JSONL | ✓ | ✓ |
| 圖片分類目錄 | — | ✓ |

外部格式對幾何與 metadata 的支援不同。需要保留完整標註、來源與審核資訊時，使用原生格式備份。YOLO 多邊形無法精確表示遮罩孔洞，轉換影響會在匯出前列出。

模型封裝輸出至專案的 `model-exports/`，包含權重、設定、評估、來源紀錄及雜湊清單，不包含訓練圖片。

## 保存與更新

每個專案的資料庫、原圖、固定資料版本、Run、模型、候選標註、模型匯出與編輯器同步資料都保存在 `data/projects/<專案名稱>__<識別碼>/`。備份前先停止訓練並關閉工作台，再複製該專案資料夾；CVAT 執行環境、虛擬環境與另行下載的基礎權重不包含在專案內。

「設定 → 更新與版本」可檢查並套用本機已變更的程式檔案。這個功能負責驗證及重新啟動，並非從 GitHub 自動下載新版；套件需求變更時需重新執行 `bootstrap.ps1`。
