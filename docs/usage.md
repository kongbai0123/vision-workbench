## 選配元件

先依 [快速開始](../README.md#快速開始) 安裝主程式，再依工作需求準備元件。線上準備環境與權重需要網路，準備完成後可在本機執行。批量找框可從已備妥的本機資料夾離線安裝。

| 元件 | 用途 | 準備方式 |
| --- | --- | --- |
| Labelme | 嵌入式標註編輯 | 隨主程式安裝 |
| GrabCut | 傳統影像分割 | 隨主程式提供 |
| SAM2 | AI 輔助分割 | 執行下方 AI 安裝指令 |
| 批量找框 | MM Grounding DINO 找框、Qwen 判讀、選用 SAM 2.1 與 Gemma 4 | 設定 → 模型與元件 → 從資料夾安裝批量模型 |
| TorchVision | Mask R-CNN、Faster R-CNN、DeepLabV3、圖片分類 | 設定中的模型與元件，或下方訓練環境指令 |
| Ultralytics | RT-DETR、YOLO26 Detect／Seg | 設定 → 模型與元件 → 安裝必要元件 |
| CVAT | 本機網頁標註編輯 | 在編輯器選擇 CVAT，依安裝引導準備 WSL 2 與 Docker |

SAM2：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\bootstrap.ps1 -AI
```

TorchVision：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\bootstrap.ps1 -Training
```

設定中心顯示以 Vision Workbench 程式根目錄為基準的安裝路徑。換電腦時，在「模型與元件」重新安裝 TorchVision 或 Ultralytics，程式會分別建立 `.venv-training` 和 `.venv-models/ultralytics`。互動 SAM 2.1 權重安裝在 `models/sam2.1-hiera-tiny`。GPU 加速需要相容的 NVIDIA GPU 與驅動程式。相機採集需要 Windows 可辨識的影像裝置。

YOLO26 Detect／Seg 預設使用預訓練權重微調，也可選擇隨機初始化；首次訓練可能下載權重。Detect 將矩形或面積標註轉為緊密框，不執行 Seg 的多邊形孔洞相容檢查。RT-DETR 目前從隨機權重開始訓練。Ultralytics 元件使用 AGPL-3.0 或 Enterprise 授權，請查閱安裝頁說明。

EfficientAD／PatchCore 目前列為規劃項目，尚未開放安裝與訓練。

## 專案流程

1. 建立專案、設定物件類別，加入圖片或採集影像。
2. 在內建編輯器、Labelme 或 CVAT 建立及修改標註。
3. 到「資料審核」確認標註並核准圖片。
4. 在「資料準備」預覽來源群組及類別分布，套用 Train／Validation／Test 分配並選擇 Train-only 資料增強配方。
5. 建立固定資料版本後，在「模型訓練」選取該版本、設定模型與參數；可先快速估時及驗證設定，準備好後再按「開始訓練」。
6. 到「評估與模型」檢查結果、匯出模型或產生預標註候選。

三個編輯器共用專案圖片與標註；切換時會等待儲存及同步完成。修改已核准標註後，圖片會回到待審核。模型輸出先保存為候選，使用者接受後加入標註，再進入人工審核。

Labelme 嵌入功能需要桌面版。CVAT 尚未支援的影片軌跡、整張標籤或形狀會阻擋同步；發生版本衝突時，先處理衝突再切換編輯器。

## 資料準備：分割與增強

資料分割管理器依「選擇方式、調整比例、檢查並套用」排列。結果分成總覽、需要注意、類別分布與手動調整；變更設定後需重新預覽，預覽不會直接修改專案。

「圖片層級平衡」直接以每張圖片為分配單位，固定種子並綜合平衡集合比例、類別出現張數、物件數及常見共現配對，不要求額外的樣本獨立性確認；相同 SHA-256 或手動指定同組的圖片仍不可拆分。相同設定與種子會得到相同結果，不是無條件隨機洗牌。「正式泛化評估」才會依拍攝批次及影片來源隔離群組。可鎖定分配單位、保留目前 Test，或手動定義不可拆分群組。此功能使用來源資訊及標註統計，未使用影像特徵辨識近似圖片。

Train 必須涵蓋所有已有標註的類別。圖片層級平衡會將 Validation／Test 的類別缺口列為警告；正式泛化評估要求 Validation 也涵蓋全部類別，若類別只有一個來源群組，需補充獨立來源才能同時訓練與驗證。Test 可選；不足的類別會標示為評估限制。

固定資料版本保存建立當時的圖片、標註及分割。修改專案後，需建立新資料版本才會用於後續訓練。既有版本可繼續用於重現及比較實驗。版本影像會在同一磁碟以 hard link 共用經雜湊驗證的不可變原圖；不支援時自動使用獨立副本。

資料增強的「每張 Train 原圖額外載入」只作用於 Train。例如 Train 有 40 張、額外載入 3 次，每輪會有 160 個訓練事件：40 個原圖入口與 120 個額外事件。資料準備頁會分別列出 Train、Validation、Test 的原圖、擴充與有效數量；新增事件不會重新分割，也不會加入 Validation／Test。

每個事件在載入時重新抽樣轉換參數，但仍源自相同原圖，因此不代表統計獨立的新資料，也不保證兩次結果互不重複。設定在畫面上屬於草稿；按「固定配方並建立資料版本」後才會保存到 DatasetVersion，新的 Run 會從固定版本讀取配方與事件數。擴充份數為 0 時維持引擎原本的線上增強方式。

Ultralytics 的 YOLO／RT-DETR 使用亮度、翻轉、旋轉、平移、縮放及 Mosaic 等支援參數；直接對比調整由原生 TorchVision adapter 使用。資料準備頁的隨機預覽是一次可能結果的示意，實際訓練會在每次載入時抽樣。

流程驗證副本允許以同拍攝來源的時間區段測試訓練流程，但評估會標示來源不獨立；其分數不能代表新場景表現。

## 訓練與評估

- 模型參數依引擎提供影像尺寸、批次大小、學習率、最佳化器及排程；草稿按專案及模型保存，正式啟動時再固定於 Run。
- 使用的分割與增強配方取自所選 Dxxx。修改 05 後需建立並選取新版本，06 才會使用新的資料分配與配方。
- 「快速估時（不訓練）」只讀取相同資料、設定與環境的歷史紀錄；「驗證設定（不訓練）」檢查參數、引擎相容性及固定圖片雜湊。兩者不會啟動訓練或下載權重。
- 實際執行後由 tqdm 依工作量更新時間；訓練、驗證、評估與保存分開計時。沒有完整階段資料時只顯示該階段估算，進度停滯則停止過期倒數。詳見[時間估算說明](time-estimation.md)。
- Validation 用於選模、門檻搜尋或訓練控制；Test 僅用於最後評估。未提供 Test 時，結果顯示尚未執行。
- 訓練頁可勾選已完成模型疊圖比較。不同定義的指標不會直接疊在一起；缺失 Epoch 會保留缺口。
- Macro IoU 是各類別在整個集合累積像素交集／聯集後的平均；Micro IoU 則合計所有類別的像素再計算。真值與預測均空白的類別顯示 N/A。
- 信心分數、Mask IoU 與 mAP 衡量不同性質；精細輪廓仍應以原圖上的真值與預測比對。
- 評估來源記錄權重選擇方式與 Test 來源是否重疊。模型比較需使用相同資料版本及評估定義。

## YOLO Seg 相容性

在資料審核階段檢查遮罩相容性；啟動 YOLO Seg 訓練時會再次檢查固定資料版本。問題清單提供圖片、類別與孔洞位置，可開啟放大預覽。

- **修補微小封閉孔洞**：依單孔大小、總像素、相對面積及寬高門檻產生訓練相容副本；實際門檻以模型參數為準。
- **嚴格無損**：無法精確轉為多邊形時阻擋訓練。

相容處理只寫入 Run 的 YOLO 資料副本，並保存轉換報告。超過門檻的孔洞及分離區塊需人工處理，或使用能讀取原生遮罩的模型。

## 支援格式

| 格式 | 匯入 | 匯出 |
| --- | :---: | :---: |
| Vision Workbench 原生格式 | ✓ | ✓ |
| COCO | ✓ | ✓ |
| YOLO Detection／Segmentation | ✓ | ✓ |
| LabelMe | ✓ | ✓ |
| JSONL | ✓ | ✓ |
| 圖片分類目錄（工作台封裝） | ✓ | ✓ |

外部格式對幾何與 metadata 的支援不同。需要保留完整標註、來源與審核資訊時，使用原生格式備份。YOLO 多邊形無法精確表示遮罩孔洞，轉換影響會在匯出前列出。

「資料匯出」位於「開啟資料夾」旁。匯出只包含已核准圖片，會同時建立資料夾與 ZIP；跨主機使用時，複製 ZIP 並完整解壓縮。在「採集與匯入」選擇解壓後的資料夾，可匯入圖片及標註；若只選其中的圖片，工作台也會尋找資料集根目錄的 `data.yaml`／`annotations.json`／`project.json`／`dataset.json`，配對對應的標註。匯入預覽會列出每張圖的標註數。已存在但沒有標註的相同原圖可補入標註，之後須重新審核；已有不同標註的圖片不會被覆蓋。ZIP 不含模型權重。

模型封裝輸出至專案的 `outputs/models/`，包含權重、設定、評估、來源紀錄及雜湊清單。

資料集匯出的輸出位置留空時，會儲存在目前專案的 `outputs/datasets/`。如需交付至其他位置，可選擇外部資料夾。專案內的既有匯出紀錄會解析到遷移後的目錄。

## 保存與更新

每個專案的資料庫、圖片、影片、標註原檔、固定資料版本、Run、模型、匯出與編輯器同步資料都保存在 `data/projects/<專案名稱>__<識別碼>/`。等任務完成後，從專案資料庫建立完整備份 ZIP，並在另一台相容版本的工作台選擇「還原專案」。目的主機依需要準備模型執行元件、CVAT 與基礎權重。

「設定 → 更新與診斷」會在背景檢查 `origin` 的 `vX.Y.Z` 版本標籤，顯示目前版本與 GitHub 最新版本。有新版時以紅點提示，每 10 分鐘重新檢查一次，也可手動重查。按「從 GitHub 更新」後，工作台會等待背景工作完成、保存編輯內容、自動備份本機程式修改，再下載、驗證及自動重新啟動。主程式依賴需要更新時，會在舊程序退出後自動安裝，沿用原資料位置。

本機程式備份的識別與復原紀錄保存在 `.git/workbench-update-backups/`；更新成功後保留備份，避免把舊修改自動套回而覆蓋新版。下載失敗不會移除修改；套用失敗會恢復原修改與暫存狀態。`data/`、模型、執行環境及無關的本機產物不會被更新覆蓋。Git 合併中、不同提交歷史或沒有遠端追蹤來源時，更新會保留原內容並顯示原因。

同頁的「本機程式檔案」另外每 2.5 秒比對執行中程式與磁碟上的原始碼；若原始碼已從外部更新，可驗證並重新啟動套用。這項本機操作不會從 GitHub 下載新版。

### 私人 GitHub 儲存庫

私人 repo 也可提供版本檢查與一鍵更新。每台電腦都需要保留 `.git` 的安裝副本、Git for Windows，以及可在背景讀取該 repo 的授權。HTTPS 可先在終端機透過 Git Credential Manager 登入；SSH 可使用已設定的金鑰及代理程式。工作台的背景 Git 作業會沿用這些憑證，登入應先在終端機完成。 [GitHub 憑證設定](https://docs.github.com/en/get-started/git-basics/caching-your-github-credentials-in-git?platform=windows)

在安裝資料夾執行下列指令，第一行應列出版本標籤，第二行應顯示預期的追蹤分支，例如 `origin/main`。

```powershell
git ls-remote --exit-code --tags origin 'refs/tags/v*'
git rev-parse --abbrev-ref --symbolic-full-name '@{upstream}'
```

版本提示讀取 `origin` 的標籤，安裝更新則快轉目前分支的遠端追蹤版本。發布新版時要將程式提交及對應的 `vX.Y.Z` 標籤推到遠端。GitHub 的原始碼 ZIP 解壓後缺少 `.git`，需以可追蹤遠端的 Git clone 使用這套更新流程。

標註頁切換圖片或儲存修改時會保留左側影像清單的捲動位置，並讓目前選取的圖片維持在可視範圍；使用鍵盤操作時也會把焦點留在選取項目。


## 模型中心分頁與評估下載（v2.21.0）

進入「07 評估與模型」，從左側選取模型後，在右側切換「總覽／訓練設定／評估報告／辨識對照／外部試跑」。標題下保留模型、Run、固定資料版本與類別數，避免把匯出編號誤認為模型版本。

- **訓練設定**：參數在區塊內捲動，可切換「只看變更」比較上一個同引擎模型。
- **評估報告**：切換 Test／Validation 查看已保存的指標，使用「下載評估 JSON」保存報告。歷史紀錄沒有的逐類別資料不會補造。
- **辨識對照**：選擇 Test 或 Validation，按「執行標註比對」重新推論固定資料，不需要重訓。每頁四張 Ground Truth／Prediction，可篩選 TP、FP、FN；點圖片標題可展開逐張檢視。
- **下載**：本批對照 PNG 保存目前篩選與頁次；辨識 JSON 與統計 CSV 包含整個評估集合。JSON 記錄信心門檻、Box IoU 門檻與模型來源。桌面版會詢問儲存位置。

TP／FP／FN 使用依信心分數排序、同類別、一對一 Box IoU 配對；遮罩在此以外接框比較，不是 Mask AP，也不等同訓練報告的 mAP。辨識結果屬於目前試跑工作階段，需要保留時請下載。
