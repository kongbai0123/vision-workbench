# 耗時任務的時間提示

一般背景工作、採集面板、元件安裝與背景訓練提示共用 `web/task-timing.mjs`。

- 不顯示已耗時計數、張數計數或按計數換算的任務進度條。ETA 明確標示為目前階段的近似剩餘時間，不承諾整個流程的完成時間。
- 最近最多 12 個不同進度值，至少 4 個樣本且跨度至少 5 秒後，才依進度斜率估算。
- 重複輪詢不算新樣本；沒有可量測百分比（例如下載輸出、等待 GPU、模型載入）時不製造倒數。
- 進度下降、階段更換、暫停／恢復會重新取樣。長時間無新進度時隱藏 ETA，恢復進度後重新取樣。
- 暫停時間不計入本次觀測耗時，終態凍結時間；百分比 100 仍須等待真正成功回應。
- 前端重新載入會重新觀測；背景訓練依 Epoch 比例估算訓練階段，不包含後續評估，早停可提前結束。
- 採集面板的固定階段百分比不當作速度樣本，只有背景工作回報的進度進入估算。
- 沒有可靠樣本時直接顯示「目前無法估算完成時間」，不能以持續增加的數字冒充剩餘时间。訓練圖表的 Epoch／Batch 診斷資料不受影響。

驗證：`node --test tests/ui_*.test.mjs`；隔離 Qt 桌面回歸 `tests/desktop_workflow.py`。

匯入預覽／確認 API 已接上背景工作進度，並以 `progress_phase` 區隔掃描、品質分析、來源驗證、保存及交易提交，避免輪詢跨過短暫階段時沿用上一階段速率。

掃描階段由 `import_sources(paths, progress=...)` 回報實測百分比：先把拖入路徑歸成解析單位（同一個 SAM2 session、YOLO 資料集或 verified 資料夾只算一個單位），單位內再依已解析的圖片或檔案前進。百分比只增不減；進度回呼拋出的取消例外不會被當成匯入問題吞掉，因此掃描中也能暫停／停止。
