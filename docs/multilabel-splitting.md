# 多類別資料分割

資料準備先選擇「資料用途」，再選擇多類別平衡目標。圖片與其全部標註永遠屬於同一集合；相同 SHA-256 的圖片在任何模式都不得跨集合。

管理器依三個步驟排列：先用用途卡片選擇分配方式，再調整 Train／Validation／Test 比例，最後從「總覽、需要注意、類別分布、手動調整」檢查預覽。套用按鈕固定在視窗底部；任何設定變更都必須重新預覽，預覽本身不會修改專案。

## 資料用途

- 圖片層級平衡（建議）：直接按圖片分配，不受拍攝批次數量限制，也不需要額外確認。Train 缺少類別仍阻擋，Validation／Test 缺類別改為警告。完全相同的圖片及手動指定同組的圖片仍保持在同一集合。
- 正式泛化評估：拍攝批次、影片來源、相同圖片及手動群組都不得跨集合。Train 與 Validation 必須涵蓋全部已有標註類別。
- 寬鬆實驗：依種子按圖片單位隨機分配，來源與類別缺口只警告。結果不能宣稱為獨立泛化能力。
- 全資料最終訓練：所有核准圖片進入 Train，不保留 Validation／Test。僅應在模型、參數與訓練輪數已由先前實驗決定後使用；結果不產生可比較的泛化評估。像素原型基準不支援此模式。

## 平衡目標

- 綜合平衡：同時考量類別出現張數、物件數與常見共現配對。
- 類別出現張數：每張圖片對每個類別最多計一次。
- 物件數量：依框、遮罩等標註實例數量分配。
- 類別共現配對：加強同圖類別配對的分布，例如 A＋B、A＋C。

四種平衡目標都支援多類別圖片。它們是軟性最佳化目標，不會把一張圖片拆成多份，也不會覆寫標註。

「來源群組不足」只適用於啟用來源隔離的正式泛化評估。圖片層級平衡會顯示圖片與類別覆蓋不足，但不會用拍攝來源數量干擾一般訓練分配。

建議模式使用固定種子的可重現最佳化搜尋，不是任意洗牌。相同核准資料、標註、比例、平衡目標、鎖定與種子會得到相同分配；變更種子只用於在同樣限制下尋找另一個可比較方案。只有「寬鬆實驗」明確採用按圖片的隨機分配。

## 永久硬限制

- Train 必須非空，且包含每個已有標註的目標類別。
- 需要評估的用途必須有非空 Validation。
- 完全相同的圖片不得跨集合。
- 圖片與標註必須一起移動，格式與模型任務相容性檢查不因用途而放寬。
- 全資料最終訓練不能使用依 Validation 指標控制的 Plateau 學習率。

預覽會保存演算法版本、用途、來源隔離政策、平衡目標、種子、比例、分配與警告。固定 DatasetVersion 與 Run 會繼續保存這些資訊，監控頁據此標示正式評估、圖片層級平衡、寬鬆實驗或無獨立評估的最終訓練。
